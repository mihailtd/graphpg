# Changelog

Releases are tagged `vX.Y.Z`; each one has generated notes on the
[Releases page](https://github.com/mihailtd/graphpg/releases). This file records the highlights.

## Unreleased

- **Rate limits** (`limits.rate_limit`, #17, off by default): a token bucket (GCRA) per client over GraphQL and REST, keyed by the verified token's `sub` (`key_claim`) or the IP address (`X-Forwarded-For` from `trusted_proxies` only), with `anonymous` and `authenticated` rates. Answers carry `RateLimit-Limit` / `-Remaining` / `-Reset`; a refused request is `429` with `Retry-After` and `RATE_LIMITED`. In memory, per instance.
- **Persisted queries** (`graphql.persisted_queries`, #19, off by default): Apollo's automatic persisted queries (`extensions.persistedQuery.sha256Hash`), a manifest of operations (Apollo's format, or a map of ids to texts) named by `documentId` or hash and validated against the schema at startup, and `allow_list` to run only the manifest's operations (`OPERATION_NOT_ALLOWED`, `/export` included). Off, a request naming one is `PERSISTED_QUERY_NOT_SUPPORTED`.
- **`GET /graphql`** for queries (a mutation is `405`), so persisted queries can be cached by URL.

- **Observability** (`telemetry:`, [guide](docs/observability.md)), for Prometheus, OpenTelemetry collectors and the Grafana LGTM stack. Metric names follow the OpenTelemetry semantic conventions, so scraped and pushed metrics read the same:
  - *Metrics:* Prometheus at `/metrics` (`telemetry.metrics`: on in dev, off in prod, optionally on a port of its own). They cover HTTP requests by route template, GraphQL operations by name and error code, database operations by type and SQLSTATE, connection pools, cache hits and planning time.
  - *OTLP/HTTP export* of traces, metrics and logs (`telemetry.otlp`: endpoint, headers, per-signal switches).
  - *Traces:* a server span per request with W3C `traceparent` propagation and PostgreSQL client spans; `telemetry.traces.sample_ratio`.
  - *Logs:* JSON log lines with request and trace ids (`telemetry.logs`).
  - *Build:* the `otel` feature is now on by default.
- **REST API** at `/rest`, planned onto the same engine as GraphQL: typed filters, ordering, keyset pagination, embedding, single-row reads and writes with `ETag` / `If-Match`, nested writes, bulk creates, aggregates and grouped aggregates, functions (`/rest/rpc/…`), search methods and global search, `Prefer: previous` (`RETURNING OLD`), views. Errors are RFC 9457 `application/problem+json` with the typed constraint codes, masked in production.
- **Planned & estimated counts over REST**: `Prefer: count=planned` uses PostgreSQL planner row estimates (`EXPLAIN` / `reltuples`); `Prefer: count=estimated` uses exact counting below `limits.count_threshold` (new, default 10,000) and planner estimates above it. Emits `Preference-Applied: count=...`, `X-Total-Count`, and `X-Total-Count-Estimate: true` headers.
- **Custom SQL problem responses**: PostgREST `PTxxx` SQLSTATE codes (e.g. `ERRCODE = 'PT402'`) and the new `errors.map` configuration map database exceptions and constraint names to custom RFC 9457 Problem Details responses (status, code, title, type, hint, extensions) and GraphQL `extensions.code`, unmasked in production for `PTxxx`, masked to the title for `errors.map` entries.
- **Table-per-type (CTI) hierarchies over REST & OpenAPI**: Parent tables in CTI hierarchies automatically select `__typename` and subtype columns with type conditions on REST reads (subtype columns also work in `filter` and `order`, over GraphQL as well), and are represented in OpenAPI schemas as a `oneOf` union across subtypes with a discriminator on `__typename`.
- **Schema in the REST path** (#122): `/rest/{schema}/{resource}` and `/rest/{schema}/rpc/{function}` (and everything below them) reach each of several `database.schemas` unambiguously, same-named tables and functions included; `/rest/{resource}` stays the default schema's shortcut. Only the schemas of the catalog have paths, and the OpenAPI document lists the concrete ones, with an operation id and components per schema.
- **Controls inside an embedding** (#118): `fields[posts]`, `filter[posts][…]`, `order[posts]`, `first[posts]` and `offset[posts]` for each `include`d relation (also in a single-row read and a search body), `inner=` / `anti=` for inner joins and anti-joins, `order=author.username` for a to-one relation's column, and computed relationships (mounted functions) selectable through `include` and `fields`. Listed per relation in the OpenAPI document.
- **Collection writes over REST** (#116): `PATCH` and `DELETE` on `/rest/<table>` by the list's `filter` (refused without one unless `unfiltered=true`, bounded by `limits.bulk_rows` and rolled back above it, `X-Affected-Count`), bulk upsert with `PUT /rest/<table>` (`conflict`, `resolution=merge|ignore`, `update`), `missing=default|null` for bulk writes, `application/merge-patch+json` and, for one row, RFC 6902 `application/json-patch+json`. `limits.bulk_rows` now also bounds GraphQL `update<Types>(where:)` and `delete<Types>(where:)`. Fixed: a GraphQL update or delete by filter selecting no rows in its payload failed with a parameter error.
- **Change events as OpenAPI 3.1 `webhooks`** (#100): `entities.<table>.events` (`operations`, `description`) adds one webhook per change (`orders.insert`, `.update`, `.delete`) typed from the table's row schema (`old` and `new`). Delivery belongs to the event-trigger epic.
- **REST benchmark against PostgREST** (#63): `benchmarks/rest` (k6 script, schema and data, `compare.sh`) runs the same lists, embeddings, paginations and writes against graphpg and PostgREST on one database; results and caveats in `docs/comparison.md`.
- **GraphQL and OpenAPI parity** (`docs/graphql-openapi-parity.md`): what each API knows about the database now exists in both.
  - *REST gets what GraphQL had:* hierarchies (`include=ancestors`, `depth[…]`), exclusive arcs (`include=target`), temporal keys (`asOf`, `asOf[…]`), computed fields with arguments (`args[field][name]`), per-row cursors, window values and running sums (`cursors`, `window`, `running`, `partition`), aggregate `sets` with filters of their own, access by a unique key (`?by=`), full-text `highlight`, JSON `path[column]`, `GET /rest/node/{id}`, NDJSON lists, `X-Debug-SQL` / `X-Debug-Explain` in dev, camel-case `order` names (`messagesCount`).
  - *The OpenAPI document states what the API accepts:* the filter operators of spatial, `ltree`, full-text and multirange columns, every `order` option, `<table>ErrorCode` / `<table>Problem` for 400, 409 and 422 answers, the relations a row carries when embedded, `/export` and `/import/{type}`.
  - *GraphQL gets what REST had:* `@constraint(…)` (the `CHECK` and `varchar(n)` keywords of the document) on fields and inputs, `totalCount(estimate: true, exactBelow: n)`, and `limits.require_filter` with `unfiltered: Boolean` on `update<Types>` / `delete<Types>`.
- **OpenAPI 3.1** document generated from the catalog and configuration: typed parameters, nested-write bodies (the GraphQL input types), the configured limits; JSON or YAML; served at `openapi.path` and shown by the bundled **Scalar** reference (which now follows `openapi.path` and works without `openapi.spec`).
- **Safety limits** (`limits:`) shared by GraphQL and REST and enforced on the plan: page size (default and maximum), depth, cost, bulk rows, aggregate groups, request body size, and `statement_timeout`. GraphQL previously had none: `first` above `limits.page_size.max` is now an error and plain lists are cut at that size.
- **Pinned schemas**: `graphpg schema export [--check]`, `graphpg export-openapi`, `export.openapi`, and `export.pin` (`fail` in prod, `warn` in dev) compare the exported GraphQL SDL, subgraph and OpenAPI files with the database at startup.
- Fixed: REST rows returned composite, range and multirange columns as empty objects; the OpenAPI document described `bigint` / `numeric` as numbers (they are strings), `json` as objects, `bytea` as binary and enums by their database labels.
- **CORS** is configurable (`server.cors`: origins, methods, headers, credentials, `max_age`). It was permissive everywhere; it is now open in dev and off in prod until origins are listed.
- **Error detail** (`errors.detail`: `masked` in prod, `full` in dev) for GraphQL and REST; GraphQL database errors were shown as they came. A privilege or Row-Level Security refusal is now `PERMISSION_DENIED` (REST: 403) in prod.
- **Introspection switch** (`graphql.introspection`, off in prod) and the **SDL over HTTP** (`graphql.sdl`, `/schema.graphql`, and `/subgraph.graphql` with federation).
- **REST media types**: CSV lists (`Accept: text/csv`, `406` otherwise), CSV bulk creates, `multipart/form-data` writes, the bytes of a `bytea` column at `/rest/<table>/<key>/<column>`, `OPTIONS` with `Allow` / `Accept-Post` / `Accept-Patch`; `HEAD` and `OPTIONS` are in the OpenAPI document.
- **OpenAPI inference**: `CHECK` constraints as JSON Schema keywords (bounds, `multipleOf`, length, `pattern`, item counts), Single Table Inheritance as `oneOf` with a `discriminator`, and `links` from foreign keys on the single-row `GET`.
- **REST ranges**: `Range: items=A-B` on lists answers `206` with `Content-Range` (the total with `Prefer: count=exact`) or `416`; every list sends `Accept-Ranges: items`.
- **REST filters**: `regex` / `iregex`, `isDistinctFrom`, `…Any` / `…All` of a list (also in GraphQL filters), `or` / `and` / `not` groups in the query string, array and JSON operators in `GET`, and range filter operators (`contains`, `strictlyLeftOf`, `strictlyRightOf`, `adjacentTo`, `overlaps`, `containedBy`) accepting `[lower,upper)` string bounds and JSON input objects.
- **HTTP semantics & tracing**: `X-Request-Id` middleware echoes incoming request IDs or generates a UUIDv4 on all responses and error payloads; `Server-Timing` latency header emitted in dev mode; conditional reads on `GET` and `HEAD /rest/{resource}/{key}` with `If-None-Match` answering `304 Not Modified` with no body.
- **Operational probes**: `/live` (liveness probe answering 200 OK) and `/ready` (readiness probe validating database connectivity via `SELECT 1`, returning 503 if unreachable).
- **RPC improvements**: functions with a single `json` or `jsonb` parameter accept raw JSON bodies directly without the `{"args": …}` wrapper.
- Docs: a [comparison with PostgREST](docs/comparison.md#compared-with-postgrest), the REST API guide, safety limits and pinned schemas in the configuration guide.

## 1.0.1 - 2026-10-04

First public release.

- GraphQL generated from PostgreSQL catalogs: relations, Relay connections with keyset pagination, filters, aggregates, search, nested writes and typed constraint errors.
- OAuth 2.0 bearer tokens with Row-Level Security, schema pruning from `GRANT`s, Apollo Federation v2 subgraph mode, `@defer` / `@stream`.
- Container image on the GitHub Container Registry: a static binary on `distroless/static`, running as a non-root user, signed with Sigstore. Tagged `X.Y.Z`, `X.Y`, `X`, `latest` for releases, and `sha-<short hash>` and `edge` for every commit on `main`.
- Graceful shutdown on SIGTERM.
