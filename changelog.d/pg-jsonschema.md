- **pg_jsonschema, completed** (#217, [guide](docs/extensions.md#pg_jsonschema)):
  - *Domains:* a `json` / `jsonb` domain checked by `jsonb_matches_schema(…, VALUE)` types every column declared with it, through one OpenAPI component, `Json.<Domain>`. Domains in another schema than the exposed ones turn the integration on too.
  - *References:* a schema with `$defs` / `definitions` and `"$ref": "#/…"` is a component of its own (`Json.<table>.<column>`) whose references resolve in the document; before, they pointed at the document's root and dangled.
  - *Older drafts:* a schema declaring draft-04, -06, -07 or 2019-09 is rewritten where JSON Schema 2020-12 (OpenAPI 3.1) reads it differently (tuple `items`, `additionalItems`, `dependencies`, draft-04's boolean exclusive bounds, keywords beside a `$ref`).
  - *More forms:* `column IS NULL OR jsonb_matches_schema(…)` and the call `AND` other conditions type the column too.
  - *Errors that say why:* a rejected value's error carries `validationErrors` (GraphQL `extensions`, REST problem document): each failed keyword and a JSON Pointer to where in the value, computed with the validator pg_jsonschema uses once the database has refused the write; in a bulk write, `fields` names the failing row.
- Fixed: a value a domain's `CHECK` rejects (`CREATE DOMAIN zip AS text CHECK (VALUE ~ '^\d{5}$')`) answered `500 INTERNAL_SERVER_ERROR`, because PostgreSQL names the domain rather than the table and column. It is now `<COLUMN>_INVALID` (REST `422`) on the column and row written, a new value of `<Type>ErrorCode` for columns of checked domains (re-export pinned schemas). A domain's `CHECK` constraints also give its columns their OpenAPI `pattern`, length and bound keywords and the SDL's `@constraint`, like a column's own.
