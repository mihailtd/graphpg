- **Fixes found by exploring a large schema (FHIR R5, 177 tables) and fuzzing its inputs**, each with a regression test:
  - **Many-to-many relations** listed a row once per junction row linking it (a person with two roles in a team twice), so `totalCount` and the pages disagreed and keyset pagination skipped rows. They are now a set (`EXISTS` on the junction), in lists, connections and relation filters (`some`, `count`).
  - **`min` / `max` of `uuid`, `boolean`, `macaddr`, `macaddr8`, `ltree` and `citext` columns** failed (PostgreSQL has no such aggregates); they are computed in each type's own order. **`min` / `max` of a range column** returned `{}` (a scalar computed for an object type): they are the first and last range in the range type's order, with their bounds.
  - **A connection selecting only `totalCount` (or aggregates) with `after` / `before`** failed (the cursor was bound for a page not read).
  - **Input the database cannot take is refused as input** (`BAD_USER_INPUT`, REST `400`) instead of failing with a server error: cursors the connection did not issue, enum values passed in variables, text with a NUL character, invalid JSON paths and regular expressions, and `LIKE` patterns ending with the escape character (which failed only when a row matched up to it).
  - **A JSON string compared with a `json` / `jsonb` column** (`equalTo: "draft"`) was bound as raw text (an error, or no match); `json` columns now compare as `jsonb`, whitespace aside.
  - **A table named like one of graphpg's own types** (`subscriptions`, `page_info`) clashed with it: its type takes its schema's name in front (`PublicSubscription`), as tables clashing across schemas do.
  - **Startup and schema reloads on large schemas: 22 s to 0.7 s**, the `@constraint` and JSON Schema keywords of every column no longer compiling six regular expressions per column (SDL 3.1 s to 15 ms, OpenAPI 5.7 s to 0.3 s on 177 tables); the OpenAPI document is built when first served, not three times at startup; an unchanged pinned OpenAPI file is compared as text, without parsing it.
  - **`GET /rest`** answered `hello world`; it lists the resources and functions, as links.
  - **Dev mode**: `X-Debug-SQL` / `X-Debug-Explain` headers are capped at 8 KiB (larger ones broke Node clients and proxies), the full value served at `/debug/sql/{id}`; without a superuser, catalog polling now sees every change the API is built from (it only saw new relations and functions, and nothing when `database.schemas` was not set); the watcher logs through `tracing` like the rest of the server.
- **Exploratory end-to-end tests** (`e2e/src/explore.ts`, `pnpm --filter @graphpg/e2e explore <url>`): the schema's own offering crawled and fuzzed; the end-to-end suite runs them on the blog schema, and subscriptions end to end over SSE and WebSocket.
