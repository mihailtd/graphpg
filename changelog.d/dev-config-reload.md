- Fixed: in dev mode, an edit to the config file rebuilt the schema but left the served and exported OpenAPI document and the limits requests were held to on the startup configuration (#214). The settings a request reads (`limits`, `errors`, `rbac`, `debug.statements`, and everything that shapes the schema) now change together, in the contract and at runtime. A changed setting that is fixed at startup (`server`, `auth`, `limits.rate_limit`, `telemetry`, …) is logged by name as needing a restart instead of being ignored silently; [the configuration guide](docs/configuration.md#editing-the-config-in-dev-mode) lists both. For embedders: `ServerState`'s `config`, `limits`, `errors` and `mask_errors` fields are now read through `ServerState::settings()`, and `ServerState::reload_with_config` swaps them with the schema.
