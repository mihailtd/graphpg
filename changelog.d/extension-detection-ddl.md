- **Extension integrations stay on while other schemas change** (#270): the check that detects pg_jsonschema's use ran `pg_get_constraintdef` on the constraints of every schema, and failed when another transaction dropped one of those tables at the same time. The integration was then switched off until the next reload: the API lost its JSON Schemas (and with `export.pin: fail`, a reload drifted from the pinned files). The check now reads only the inspected schemas' constraints. A catalog query that fails because of concurrent DDL is run again, and if it keeps failing the inspection is refused (a reload keeps the current schema) instead of serving without the integration. The single-table-inheritance checks no longer drop their errors silently.
- **Tests**: the replica routing tests no longer assume that a primary never replayed WAL (one that went through crash recovery reports the last LSN it replayed).
