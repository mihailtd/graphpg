- **Fixes found exploring auth claims, concurrent DDL and failover**, each with a regression test:
  - **Global IDs are typed everywhere**: a key argument, a foreign-key input or filter, and a Federation `_entities` representation refuse (or, for `_entities`, find nothing for) the global ID of another type, which used to be decoded whatever its type (a `User`'s ID resolved the `Forum` with the same key).
  - **A token with a NUL character in a claim** failed every request with a 500 (PostgreSQL settings cannot hold one): it is refused (`401`). **A claim cannot replace `claims_setting` or a mapped setting** through `session_variables.prefix`.
  - **`GET /rest` was not authenticated**: it listed resources for invalid tokens, and without a token when anonymous requests are refused.
  - **A connection whose request panicked mid-transaction** went back to the pool inside that transaction, with the request's role and claims: it is closed instead.
  - **Requests caught by a schema change** (a column renamed or dropped while they ran, or before the server read the schema again) failed as `INTERNAL_SERVER_ERROR`: they are `SCHEMA_CHANGED` (`503`, retryable), and the server reads the database again by itself, also without DDL watching. Under continuous DDL, the k6 soak went from 111 113 engine failures to none.
  - **Requests whose connection the database ended** (a restart, a failover) failed as `INTERNAL_SERVER_ERROR`: they are `DATABASE_UNAVAILABLE` (`503`, retryable), as GraphQL requests that cannot get a connection now say too.
  - **Reading the catalog while DDL runs** could panic (a column dropped meanwhile has null privileges).
  - **Dev mode's DDL watcher**, once its connection failed (a database restart), reloaded the schema about four times a second forever; it now polls, reconnects, and stays quiet.
- **`benchmarks/explore/auth.js`**: k6 requests with valid tokens carrying hostile claims and invalid tokens of every kind; neither may get a 5xx, nor the other's answer.
